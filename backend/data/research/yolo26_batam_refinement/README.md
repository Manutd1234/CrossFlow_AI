# YOLO26 Batam vehicle-counting experiment

The serving choice is the official COCO-pretrained **YOLO26s at 1280 pixels, confidence 0.25**. It was selected using the three fixed Batam validation photos, before this experiment reopened the four previously consumed test photos. The selected checkpoint is pretrained; the separately trained nano candidates did not win validation.

The real nano transfer-learning run used nine Batam photos with 56 assistant-reviewed boxes, 20 epochs, batch 3 and nominal batch size 3. Its execution receipt records **60 optimizer updates**, with gradient accumulation 1. Nano validation mean count error fell from 5.33 to 2.00 vehicles per image. The selected small model at higher resolution achieved 1.33 on the same three validation images (22 boxes). Choosing among several configurations on only three validation images can overfit that small development set.

The reused Batam diagnostic has four photos and 18 vehicle boxes. Mean absolute count error was **1.00 vehicle per image**, exact counts matched **1/4**, and **3/4** were within one vehicle. IoU-0.5 detection precision and recall were both 88.9%. These are pilot diagnostics from assistant-authored labels, not human-certified Batam CCTV accuracy. The aggregate predicted total equaled the labeled total, but per-image errors remain; matching aggregate totals is not perfect counting. No 99–100% or Google comparison claim is supported.

`model.pt` has SHA256 `646f8bc3fe0a656803d95c294f7852321748cb29d13466a1af8862e2db384a1b`. `selection_frozen_before_reused_batam_test.json` retains the validation decision. `serving_policy.json` binds the full resolution, confidence, class, size, NMS and preprocessing policy to the runtime detector identity `yolo26s-646f8bc3fe0a6568-p9cceb5b6b9869bbf`. A camera's independent validation reference must bind this runtime identity. Four real serving calls matched the frozen offline detections and counts in `serving_parity.json`.

Inference runs locally in `.venv-yolo26`, without model downloads, image uploads or image persistence. Warm CPU inference measured roughly 0.1–0.2 seconds per diagnostic photo on this machine; first model load takes longer. Camera congestion needs the separate temporal analyzer, registered road/background regions, usable timestamps, permission and independent camera validation. This model does not measure physical speed, queue metres or travel time.

The program refuses to overwrite existing experiments; use a new output directory containing the documented official checkpoint downloads for another run. It never modifies the original source split, annotations or previous model checkpoints. `runtime_config/` and environment directories are local runtime state and should not be redistributed as model evidence.
